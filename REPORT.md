## Задание 5. Языки разметки и генераторы

### Действия и результат

Исправленная configuration.md перенесена целиком в compare/configuration.rst отдельным PR `compare-markup`.
Сохранены заголовок, абзацы, список, все шесть параметров, YAML, примечание и ссылка на «Работа с сервисом».
Таблица оформлена list-table: больше строк, зато не нужно выравнивать границы ячеек вручную.
В Markdown короче таблицы и ссылки; в reStructuredText удобны типизированные роли и директивы, но важнее отступы и синтаксис.

Роль :doc:`usage` относится к Sphinx, а не к базовому reStructuredText.
GitHub использует собственный просмотр разметки, не собирает проект Sphinx и не получает его карту документов.
Поэтому гарантировать рабочую междокументную ссылку в просмотре GitHub нельзя; представление проверяется отдельно и фиксируется ниже.
В compare/ не создаётся полноценный проект Sphinx: это сравнительный фрагмент, а рабочая документация по-прежнему собирается MkDocs из docs/.
Источник: [роли Sphinx](https://www.sphinx-doc.org/en/master/usage/referencing.html#role-doc).

| Сценарий | Язык | Генератор | Главный довод | Главный риск |
|---|---|---|---|---|
| А: Python API и PDF | reStructuredText | Sphinx + autodoc, LaTeX/PDF | Справочник из docstrings и руководство из одного проекта | Зависимости импортируемой библиотеки и отдельная настройка PDF/шрифтов |
| Б: RU/EN, версии, команда React | Markdown/MDX | Docusaurus | Версии, локализация и React-компоненты подходят команде | Стоимость Node/React-сборки и поддержки переводов всех версий |
| В: две редакции HTML/PDF | AsciiDoc | Asciidoctor + Asciidoctor PDF | include и условные блоки позволяют переиспользовать общие главы | Ошибки условий могут смешать редакции; нужны четыре проверки вывода |

Основания выбора: [Sphinx autodoc](https://www.sphinx-doc.org/en/master/usage/extensions/autodoc.html), [версии Docusaurus](https://docusaurus.io/docs/versioning), [локализация](https://docusaurus.io/docs/i18n/introduction), [включения Asciidoctor](https://docs.asciidoctor.org/asciidoc/latest/directives/include/).
Если выбор ограничить только MkDocs, Sphinx и Docusaurus, для В можно взять Sphinx с include, only/tags и LaTeX; это потребует дисциплины условных разделов и настройки PDF.
MkDocs подходит текущему небольшому komnata; для А понадобятся плагины API/PDF, для Б — дополнительные средства версий и переводов, для В — управление редакциями и PDF.

При реальной отправке compare-markup hook успешно проверил семь страниц: `0 errors, 0 warnings, 0 suggestions`, строгая сборка завершилась успешно.

Разница уровней Vale проверена временным файлом: «Деплой» дал 1 warning и exit 0; «Юзер» дал 1 error и exit 1.
Файл удалён после опыта и не попал ни на сайт, ни в Git.
Правило для жаргона не мешает правильному слову «конфигурация»: итоговая проверка всех страниц не даёт замечаний.
Автор получает быстрый ответ до отправки, а CI нужен для одинаковой проверки всех участников: локальный hook можно отключить или не установить.

Независимое взаимное ревью не состоялось: напарник недоступен, чужих комментариев и Approve нет.
Самостоятельная проверка — полезная замена по процессу, но не буквальное выполнение парного требования.
Не выполнен необязательный слепой эксперимент с двумя ИИ-запросами; не создана фиктивная документация старой версии.
Защита main и проверка внешних ссылок не выбраны как дополнительные задания.
Содержимое источников истины сохранено; продукт и база данных курсового проекта СудПоток не изменялись.
